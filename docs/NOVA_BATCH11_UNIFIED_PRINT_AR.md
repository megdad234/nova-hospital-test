# NOVA Batch11 — إصلاح موحد للصيدلية والمستشفى (2 نوفمبر 2026)

## سبب الإصلاح
في الصيدلية كان قالب الإيصال الحراري صحيحاً في اختبار سابق، لكن الطباعة تتم عبر `window.print()` داخل الصفحة الأم، فتحكم بها اختيار الورق A4 أو Orientation من المتصفح/تعريف الطابعة. في المستشفى، تجميع CSS الخاصة بـ A4 والطباعة الحرارية وتحديد طول متغير خلّف إيصالات متعددة الصفحات عند بعض الإعدادات. نجاح Source CI وحده لا يؤكد نجاح الطباعة على Xprinter.

## التصميم الجديد
- مصدر JavaScript واحد `.github/ci/nova_unified_thermal_engine.js` يضاف بعد Batch10 داخل الصيدلية والمستشفى دون تغيير قاعدة البيانات أو قيود البيع.
- إنشاء iframe مستقل لكل إيصال، بدون تحميل CSS أو @page من البرنامج الأصل؛ تعيين عرض الورق 80mm أو 58mm، وعرض المحتوى 72mm أو 48mm.
- حساب طول الصفحة بالاعتماد على ارتفاع **محتوى الإيصال فقط** وليس ارتفاع الـiframe؛ تعريف قاعدة @page وحيدة بطول مناسب. اتجاه عربي RTL، وأجزاء معرفات البنك والتاريخ LTR.
- الصيدلية: الاحتفاظ بقالب `receipt(s)` نفسه؛ تغيير مسار الطباعة الحرارية فقط. فاتورة مشتريات الصيدلية ونسخ A4 تظل بطباعتها الحالية.
- المستشفى: نفس المحرك للإيصال، مع الاحتفاظ بوظيفة إعادة طباعة الدفعات الجزئية وبطباعة الفاتورة الكاملة A4 ونتائج المعمل A4.
- إعدادات الطابعة الفعلية خارج صلاحية الويب؛ Chromium أو تعريف XP-80C قد يفرض Orientation أو Paper Size آخر. لا يوجد ضمان 100% حتى يتم اختبار XP-80C على جهاز المستخدم.

## اختبارات القبول
- `node .github/ci/nova_unified_print_test.js` لفحص مستند طباعة 80/58، استدعاء واحد، وعدم تسريب A4.
- `python -m unittest -q pharmacy.tests.test_nova_batch11` للحفاظ على الوظائف التاريخية.
- فحص قواعد JS، واختبارات المستشفى والصيدلية السابقة، وبناء Windows Setup / ترقية / تراجع على بيانات اصطناعية.
- اختبار فعلي نهائي: إيصال صيدلية وإيصال كاشير على نفس XP-80C (صفحة حرارية واحدة، عرض صحيح، رأس وتاريخ ومبلغ وخاتمة كاملة).

## ملاحظة مهمة
قبل تثبيت إصدار على نظام فيه بيانات، خذ نسخة احتياطية قابلة للاسترجاع. بعد التحديث نفذ إعادة تحميل كاملة للمتصفح (Ctrl+F5) ولا تغير إعدادات الصيدلية القديمة قبل التحقق من تطابقها مع تعريف XP-80C.
