# NOVA Batch09 — شاشة البيع وكشف تحصيل الأدمن (2 نوفمبر 2026)

## المشكلات المؤكدة
- شريط الفواتير المعلقة المضاف قبل لوحتي البيع كسر افتراض قواعد CSS أن اللوحة الثانية هي سلة البيع، فعُوملت نتائج البحث كمنطقة ثابتة بارتفاع الشاشة وأصبح التمرير طويلاً.
- «عرض المعلقة» القديم يفتح صفوفاً داخل شريط محدود، وليس نافذة واضحة. الحفظ أصلاً على قاعدة السيرفر وبصلاحية الموظف الحالي، والمُستعاد لا يحجز المخزون.
- تقرير التحصيل التفصيلي للأدمن كان مواصفات معتمدة فقط؛ لا توجد شاشة تعرض البنك ورقم العملية لكل دفعة، على الرغم من وجود ملخص إجمالي الكاش والبنوك.

## التغييرات
- تصحيح توزيع اللوحات داخل شاشة POS بإسناد دور لكل لوحة (بحث، سلة)، وضبط الارتفاع والتمرير الداخلي والاستجابة للأجهزة المختلفة. الإبقاء على جميع وظائف البيع والتأمين وتعليق الفواتير وأنواع الدفع بدون تغيير.
- استبدال العرض المعلق بنافذة واضحة، تحقق من نجاح الحفظ قبل مسح السلة، واسترجاع الأصناف والعميل والتغطية وطريقة الدفع، ورسائل نجاح/فشل صريحة. يظل المستند المعلق محفوظاً حتى الحذف المتعمد، ولا يُخصم المخزون عند التعليق.
- تقرير الأدمن مفصل: حركة تحصيل أو استرداد لكل طريقة دفع، تاريخ وموظف وقسم واسم المريض والفاتورة، البنك ورقم العملية كنص. افتراضياً تحصيلات المرضى فقط لتتطابق مع ملخص البنك والكاش الأصلي؛ تسويات التأمين منفصلة أو تختار الجمع الصريح بدون تكرار.
- فلترة الفترة والطريقة والبنك والموظف، والترقيم 80 صفاً لكل صفحة؛ جميع الصفوف عند تصدير XLSX بملف Excel حقيقي من مكتبة Python القياسية وبالأرقام البنكية كنص. طباعة/PDF كامل باستخدام وضع طباعة A4 أفقي.
- بوابة واجهات التقرير تتحقق من صلاحية admin في السيرفر. تجنب تعديل قواعد البيانات التاريخية والمحاسبة الأساسية وإيرادات الصيدلية. المقبوضات القديمة غير المصنفة لا يتم تحويلها إلى بنك مفترض.
